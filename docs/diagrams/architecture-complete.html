Neo Cloud Agent 完整架构图

一个 monorepo · 12 个 package · 三个控制面进程 + 一张 worker 镜像 · 客户端只打 /v1。对标 Cursor Cloud Agent；Agent 内核是 pi-coding-agent，不自研 tool loop。对照 main 484d663 · 2026-08-31。

锁死原则：Agent loop 跑在执行面，不跑在控制面。Provider Key 和讯飞 IAT 密钥只在 llm-gateway。Worker 只有短寿命 run JWT。
客户端 入口 / 边缘 控制面（高信任） 执行面（低信任） 推理（唯一持钥） 存储 外部系统

现网应用机 · 62.234.211.200 · 4C/4G

Ubuntu 24.04 · systemd：neo-llm-gateway / neo-control-plane / neo-admin-api / Caddy。无 Docker、无 KVM。现网 HTTP 优先（备案未过不跳 HTTPS）。对话 http://62.234.211.200/，管理台 /admin/，架构海报 /architecture。

一次 Run 主路径

Client → POST /v1/runs → orchestrator 占槽 → Runtime.provision → worker bootstrap（JWT）→ pi 打 Gateway → 工具改 /workspace → /internal/events → 多端 SSE。跟进对齐 prompt / steer / followUp。
